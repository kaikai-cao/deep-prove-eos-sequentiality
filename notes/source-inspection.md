## 3. Run-side EOS handling

`zkml/src/model/llm.rs`, `run_elements_with_runner` lines 471–489:

```rust
let eos_token: N = self.md.config.eos_token.as_tensor_type_param();
let handle = {
    let stop = Arc::clone(&stop);
    thread::spawn(move || -> anyhow::Result<Vec<N>> {
        let mut generated_tokens = Vec::with_capacity(max_window);
        while let Ok(tensor) = rx.recv() {
            let token = tensor.get_data()[0];
            if token == eos_token {
                stop.store(true, Ordering::Relaxed);
                return Ok(generated_tokens);
            }
            generated_tokens.push(token);
        }
        generated_tokens.pop();
        Ok(generated_tokens)
    })
};
```

The stop flag is checked by the inference loop at lines 495–502. The EOS
token is not pushed into `generated_tokens` on that branch. This behavior
is the ground truth for EXP-01-B boundary cases.

## 4. Verifier EOS index and sequentiality check

`zkml/src/model/llm.rs`, `LLMVerifierContext::verify`, lines 835–875:

```rust
// get the actual output length: could be either `max_window`, or when an eos token is found
let eos_token = self.md.config.eos_token;
let eos_token_found = output
    .data()
    .iter()
    .take(max_window) // consider only the first max_window tokens
    .skip(user_input.len() - 1) // the first user_input.len() - 1 are not meaningful
    .find_position(|token| token.to_element() as usize == usize::from(eos_token));
let unpadded_output_len = if let Some(pos) = &eos_token_found {
    pos.0
} else {
    max_window
};

// ... proof verification at 849–852, user-input prefix check at 856–863 ...

let seq_len = user_input.len();
ensure!(
    prover_input.data()[..seq_len]
        .iter()
        .zip(user_input[..seq_len].iter())
        .all(|(a, b)| a.to_element().to_usize() == b.0),
    "user input not the same"
);

#[allow(clippy::needless_range_loop)]
for i in seq_len - 1..unpadded_output_len - 1 {
    ensure!(
        prover_input.data()[i + 1] == prover_output.data()[i],
        "next input token is not the one generated by this row pos i {}: {:?} != {:?}",
        i,
        prover_input.data(),
        prover_output.data()
    );
}
```

Index relations to check empirically:

- `find_position` returns a position **relative to the iterator after
  `skip(seq_len - 1)`**. If EOS is at absolute output index `a`, then
  `pos.0 = a - (seq_len - 1)`.
- The sequentiality loop starts at absolute index `seq_len - 1` but ends at
  `unpadded_output_len - 1 = pos.0 - 1`. These are in different bases.
- For `pos.0 < seq_len`, the range `seq_len - 1 .. pos.0 - 1` is empty, so the
  sequentiality equations are not enforced. Whether this is reachable with
  a real proof and IO is a question for EXP-01-C, not a conclusion here.
- `pos.0 == 0` (EOS at the first position of the skipped slice) evaluates
  `0usize - 1`. Debug builds panic on the subtraction; release builds wrap.
  This must be observed, not assumed, in EXP-01-B1.
- When no EOS is found, `unpadded_output_len = max_window` and the loop runs
  from `seq_len - 1` to `max_window - 1` (the intended full check).
- `take(max_window)` is applied before `skip`; if `seq_len - 1 >= max_window`
  the iterator is empty, so no EOS is found even if one exists in the
  tensor. Record as a boundary condition if encountered.

## 5. Planned minimal fix candidate (EXP-01-D only)

Convert the found position back to the absolute index before using it as the
loop bound, e.g. treat `unpadded_output_len` as `user_input.len() + pos.0`
with an explicit guard for `pos.0 == 0`, while leaving all other verifier
logic unchanged. This is a **candidate** for the control experiment; the
actual patch must be derived from observed behavior in EXP-01-B/C and its
scope checked against the acceptance rule in `EXPERIMENT-PLAN.md`.
